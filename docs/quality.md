# Android quality gates

## CI gates

GitHub Actions runs on push, pull request, and manual dispatch:

```bash
./gradlew testDebugUnitTest --stacktrace
./gradlew lintDebug --stacktrace
./gradlew assembleDebug --stacktrace
```

It also uploads:

- Android lint HTML report,
- unit test report,
- debug APK artifact.

## Wrapper validation

The workflow validates the Gradle Wrapper when `gradle/wrapper/gradle-wrapper.jar` exists. Because this repository was bootstrapped through the GitHub connector, the wrapper may be generated by the first local/Codex run.

## Kotlin formatting

The workflow checks for a `ktlintCheck` task and runs it when present. The first Codex run should add ktlint only after confirming the project builds, to keep the initial baseline simple.

Recommended plugin:

```kotlin
id("org.jlleitschuh.gradle.ktlint") version "latest-verified-version"
```

Once enabled, CI should fail on formatting violations.

## Future useful gates

- Detekt for static Kotlin analysis.
- Dependency review for pull requests.
- Instrumented smoke tests on emulator for UI startup.
- Release signing checks when a release build is introduced.
